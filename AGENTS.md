# AFTERIMAGE — Project Instructions

AFTERIMAGE is an existing full-stack music discovery and moodspace application.

## Preserve existing functionality
- Preserve the working Express and MongoDB backend.
- Preserve authentication, authorization, API contracts and data persistence.
- Preserve Jamendo music integration and actual audio playback.
- Preserve moodspaces, images, notes, Mood DNA and recommendations.
- Preserve player state, queue behavior and existing functional tests.
- Never replace working features with mock data or static demonstrations.

## Frontend reset
- The previous frontend visual design has been rejected.
- Existing React layouts, styling and component hierarchy are not design references.
- Rebuild the frontend presentation and interaction design from first principles.
- The ONLY authoritative visual references are in design/references/.
- Inspect every reference image before making design decisions.
- Do not reuse old color palettes, layouts, typography or visual concepts by default.
- Existing frontend code may be studied for functionality and integration only.
- Historical design instructions in other documents are obsolete.

## Engineering requirements
- Maintain responsive desktop and mobile experiences.
- Preserve accessible controls, keyboard operation and reduced-motion support.
- Preserve the existing single authoritative audio playback system.
- Implement actual functional React components rather than decorative mockups.
- Keep credentials private. Never print or commit environment secrets.
- Do not reset or delete MongoDB application data.
- Do not push, deploy or commit without explicit approval.
- Run lint, tests and build after implementation.

## Workflow
- First inspect the existing project and new visual references.
- Present a new visual system and proposed layouts for approval.
- Do not implement the new visual system before approval.
- After approval, perform a complete frontend visual rebuild.
